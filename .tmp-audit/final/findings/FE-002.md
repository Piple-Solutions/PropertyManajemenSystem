## Detail temuan

**What:** `getAll()` requests `page=1&pageSize=100` and the pages filter/paginate/count client-side as if that were the whole table; the backend has no `ORDER BY` (BE-035).
**Trace:** property has 130 reservations -> `/api/reservations?page=1&pageSize=100` returns an arbitrary 100 -> list shows "Showing 1–8 of 100 result(s)", status counters on the calendar page (`reservations.length`, :176-181) and invoice-code lookup (InvoiceListPage:127) are computed from that subset; newer bookings are missing with no indicator.
**Impact:** Staff cannot find or act on reservations beyond 100; wrong counts. Reached in months of normal use.
**Minimal fix:** Use server-side pagination/filters with explicit ordering (the API already supports `page`, `pageSize`, `search`, `status`, `source`, `date`); or loop through pages.
**Effort:** M | **Related:** BE-035, X-003

## Item yang digabung ke temuan ini

### X-003 — Pagination/ordering contract

Severity awal: High. 

FE assumes `pageSize=100` page 1 is the full dataset; BE caps `pageSize` at 100, returns `pagination.total` (ignored by the FE) and has no deterministic order. Either FE must page through `total`/use server filters, or BE must raise/offer an "all" mode and order explicitly.

### BE-035 — Non-deterministic pagination

Severity awal: Medium. 

**What:** All paged list queries use `LIMIT/OFFSET` without `ORDER BY` (only `activities` is ordered). SQLite gives no ordering guarantee without it; D1 may return rows in rowid order today but any index choice/`WHERE` plan can change it.
**Trace:** `GET /api/reservations?page=2&pageSize=10` with a search/status filter -> planner picks an index scan -> rows returned in index order that differs from page 1's rowid order -> items duplicated/skipped across pages. Also the FE fetches `page=1&pageSize=100` and treats it as "all" (see X-003).
**Impact:** Missing/duplicated rows in lists; newest-vs-oldest undefined.
**Minimal fix:** Add explicit `ORDER BY created_at DESC, id DESC` (reservations: check_in_date, id) to every list query.
**Effort:** S | **Related:** X-003, FE-002
